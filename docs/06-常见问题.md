# 06 · 常见问题

> 这是 README 里 FAQ 的扩展版。**按症状找**请看 [05 · 故障排查](05-故障排查.md)。

## 使用

**Q：它会替我"养号"吗？会不会刷屏？**
不会。它只在**你指定的时间**，给你**手动开启的**收件人，发**你写好的**那一条消息。
默认全发（`rotation=all`）是因为火花的规则就是"每天得有互动"。

**Q：一天发几次？**
默认一次（比如 09:30）。想多发就在任务页加时间/多跑一次手动发送。

**Q：可以只发给一部分人吗？**
可以 —— 收件人页的开关就是干这个的。也可以用 `round_robin` 轮流。

**Q：能发图片 / 表情吗？**
能，文案池里 `kind` 支持 `text` / `image` / `sticker` / `random`，
详见 [03 · 任务配置详解](03-任务配置详解.md#4-文案池messages)。

**Q：换手机 / 换电脑要重新登录吗？**
通常不用 —— 把 `data/accounts/` 整个目录拷到新机器即可。
**先备份再换**，别等丢了才发现。

## 安全与隐私

**Q：登录态存在哪？有多敏感？**
`data/accounts/main.state.json`，里面是会话 cookie + localStorage，**等同密码**。
别提交、别放网盘、备份时按密码对待。

**Q：我的好友名单会被上传吗？**
不会。所有数据都在你自己的 `data/` 目录里，工具只和 douyin.com 通信。

**Q：仓库里会不会有我的隐私？**
`data/` 和 `.env` 都在 `.gitignore` 里，不会进版本库。
即便如此，**公开仓库前仍建议自己再看一遍**。

**Q：工作台怎么保护？**
设 `HUOHUA_TOKEN`（至少 24 位随机串）。更严格可以配 `HUOHUA_ALLOWED_IPS` 只放行自己的 IP，
或者根本不暴露端口、用 SSH 隧道访问。详见 [SECURITY.md](../SECURITY.md)。

## 部署

**Q：能不能在树莓派 / NAS 上跑？**
可以，只要有 Docker 或 Python 3.11+。内存 **2GB 起步**（峰值约 800MB），512MB 必 OOM。

**Q：为什么首次登录不能在服务器上做？**
服务器没有图形界面，而且抖音的二次验证需要**人看画面填验证码**。
正确顺序：本机登录 → 拷贝登录态 → 服务器只做定时发送。

**Q：本机和服务器能同时跑吗？**
技术上能，但**不建议同一个账号两边都开定时**：既容易触发风控，也会互相顶号。
本机只用来登录和调试。

**Q：Docker 和 systemd 选哪个？**
有 Docker 就用 Docker（自带 Chromium 依赖，省心）。没有就用 systemd 或 cron。

## 行为细节

**Q：为什么有人显示"结果不确定"？**
意思是"消息**很可能已发出**，但没能确认"。常见原因是抖音把会话列表的预览
换成了系统提示，导致预览比对失效。**不会自动重发**（避免重复发送），请你手动看一眼会话。

**Q：为什么成功了却不推送？**
**设计如此** —— 成功不打扰，只有失败 / 异常才推。详见 [04 · 告警配置](04-告警配置.md)。

**Q：为什么时间有点飘？**
如果配了抖动（jitter），就会在整点后随机延后。另外每个人之间还有 20~90 秒的随机间隔。

**Q：会重复发送吗？**
定时场景有「当天已发过就跳过」的防重（依据是发送成功那一刻写入的 `contacts.json`）。
手动点发送**故意不防重** —— 因为手动的意义就是"再发一次"。
"结果不确定"也**不会**重试，原因同上。

## 开发

**Q：想改代码从哪开始？**
看 [CONTRIBUTING.md](../CONTRIBUTING.md)。改完跑：

```bash
ruff check src tests scripts && ruff format --check src tests scripts
pytest tests/unit -m unit
```

**Q：为什么要装两个 Chromium？**
有头模式用 `chromium`，**无头模式用 `chromium-headless-shell`**。
只装一个的话，无头跑起来会报 `Executable doesn't exist`。

**Q：测试会不会真的发消息？**
不会。默认都是 `unit` 标记，不碰浏览器也不联网。
`live` 标记的用例需要真实账号，**默认跳过**。
