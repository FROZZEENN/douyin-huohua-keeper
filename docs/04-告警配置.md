# 04 · 告警配置

> 设计原则：**成功不打扰，只有失败 / 异常才推**。
> 所以"今天全发成功了却没收到任何消息"—— 那是**正常现象**，不是坏了。

## 1. 什么时候会推

| 级别 | 什么时候 |
|---|---|
| `NORMAL` | 一切顺利 —— **不推** |
| `NOTICE` | 有情况但不算事故（例如本轮有人失败、定时任务压根没执行成）→ **推** |
| `WARNING` | 连续失败天数达到 `HUOHUA_WARN_THRESHOLD`（默认 **2** 天）→ 推 |
| `CRITICAL` | 连续失败天数达到 `HUOHUA_CRITICAL_THRESHOLD`（默认 **3** 天）→ 推 |

另外还有一条**每日汇总**（默认 23:30），但它的定位是「**补救提醒**」而不是日报：

- **今天一切正常 → 不推。**（消息已经发给好友了，不需要再向你报喜。）
- **只有今天出过问题才推**：今天没跑、没成功、有发送失败、或有「结果不确定」的发送。

⚠️ 它只在配置了通知通道之后才会启用 —— 没配就静默跳过。

## 2. 六个通道

在 `.env` 里配（改完重启容器生效）：

### Server酱（推荐，微信就能收）

```bash
HUOHUA_NOTIFY_CHANNELS=serverchan
HUOHUA_SERVERCHAN_KEY=SCTxxxxx          # 在 sct.ftqq.com 拿
```

### Bark（iOS）

```bash
HUOHUA_NOTIFY_CHANNELS=bark
HUOHUA_BARK_URL=https://api.day.app/你的key
```

### 钉钉

```bash
HUOHUA_NOTIFY_CHANNELS=dingtalk
HUOHUA_DINGTALK_WEBHOOK=https://oapi.dingtalk.com/robot/send?access_token=xxx
HUOHUA_DINGTALK_SECRET=SECxxxx          # 加签时填；没开加签可留空
```

### 飞书

```bash
HUOHUA_NOTIFY_CHANNELS=feishu
HUOHUA_FEISHU_WEBHOOK=https://open.feishu.cn/open-apis/bot/v2/hook/xxx
```

### Telegram

```bash
HUOHUA_NOTIFY_CHANNELS=telegram
HUOHUA_TELEGRAM_BOT_TOKEN=123456:ABC-DEF
HUOHUA_TELEGRAM_CHAT_ID=-1001234567890
```

### 通用 Webhook（自己接）

```bash
HUOHUA_NOTIFY_CHANNELS=generic
HUOHUA_GENERIC_WEBHOOK=https://你的服务/notify
```

## 3. 同时用多个通道

用逗号分隔：

```bash
HUOHUA_NOTIFY_CHANNELS=serverchan,telegram
```

> 多个通道是**尽力而为**：其中一个挂了不影响其它通道继续推，
> 但整体结果会记录成"部分失败"。

## 4. 怎么验证配好了

1. 系统设置页 → 「**通知测试**」—— 会立刻发一条测试消息；
2. 或命令行跑自检，它会检查通道配置：

   ```bash
   python scripts/healthcheck.py
   ```

## 5. 常见疑问

| 现象 | 原因 |
|---|---|
| 全部成功却没收到 | **设计如此**：成功不推 |
| 收不到每日汇总 | **今天一切正常就不会推**（这是设计）；另外没配通知通道也不启用，`HUOHUA_DIGEST_ENABLED=false` 会整体关掉 |
| 想恢复"每天都推一条" | 目前不支持 —— 策略就是「只在有问题时提醒你」。真想要的话来提 Issue |
| 想改汇总时间 | `HUOHUA_DIGEST_HOUR` / `HUOHUA_DIGEST_MINUTE`（默认 23:30）|
| 想更早/更晚告警 | 调 `HUOHUA_WARN_THRESHOLD` / `HUOHUA_CRITICAL_THRESHOLD`（前者必须小于后者）|
| 推送失败 | 看 `logs/huohua.log`，会有通道返回的具体错误 |

## 6. 安全提醒

- `HUOHUA_SERVERCHAN_KEY` 之类的值**不要提交进仓库**（`.env` 已忽略）；
- 通道 URL 里通常带密钥 —— 贴日志 / 提 Issue 前记得打码；
- 改完配置用 `python scripts/healthcheck.py` 自检一遍再重启服务。
