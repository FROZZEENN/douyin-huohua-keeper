# 02 · 扫码登录图解

> 这篇讲清楚：**二维码从哪来 → 扫完发生什么 → 登录态存在哪 → 搬到服务器**。
> 照 [01 · 快速上手](01-快速上手.md) 操作时卡在这一步，就回来看这里。

## 1. 二维码是怎么到你面前的

```
抖音登录页（无头浏览器里）
      │  工具把页面上的二维码截图
      ▼
工作台「账号」页（或 /scan.html）
      │  每 2 秒同步刷新
      ▼
你用抖音 App 扫
```

**为什么要不停刷新**：抖音的登录码寿命只有 **1~2 分钟**。
`/scan.html` 每 2 秒自动换一张，所以不存在"刚要扫就过期"的问题 —— 直接扫就行。

## 2. 扫完之后发生了什么

| 阶段 | 页面上显示 | 你要做什么 |
|---|---|---|
| 等待扫码 | 二维码 | 用抖音扫 |
| 已扫描 | 「已扫描，请在手机上确认」 | **在手机上点「确认登录」** ← 最容易漏 |
| 二次验证（可能） | 要求填验证码 | 见下面第 4 节 |
| 登录成功 | 「登录成功」 | 不用管，登录态已保存 |

> ⚠️ 很多人扫完就去干别的，忘了**手机上还有一次确认** —— 于是表现为"一直转"。

## 3. 登录态存在哪

登录成功后，凭据保存在：

```
data/accounts/main.state.json
```

里面是**会话 cookie + localStorage** —— **等同密码**：

- 不要提交进仓库（已在 `.gitignore` 里）
- 不要放网盘、不要发到群里
- 备份时按密码级别对待

## 4. 二次验证怎么办

抖音有时会要求输验证码。这时有两个入口：

1. **工作台的「登录页实时画面」** —— 页面上会显示当前真实状态；
   在下方的「要填进」里选对是第几个输入框，再点「输入内容」。
2. **`python scripts/login.py`** —— 在本机**可见的浏览器窗口**里完成，最直观。

> 二次验证需要**人工看画面**，所以**服务器 / 容器里永远做不了首次登录**。
> 这也是为什么流程必须是：本机登录 → 拷贝登录态 → 服务器只负责定时发送。

## 5. 搬到服务器

```bash
# 只拷这一个文件就够了
scp data/accounts/main.state.json root@<你的服务器>:/opt/douyin-huohua-keeper/data/accounts/

# 服务器上（注意属主，Docker 里进程 uid 是 10001）
docker exec <容器> chown -R 10001:10001 /app/data
```

服务器**不要**再登录一次：同一个账号在两个实例上各跑定时任务，既容易触发风控，也会**互相顶号**（一边登录 → 另一边失效）。

推荐的分工：

| 机器 | 角色 |
|---|---|
| 本机（有界面） | 登录、调试、手动补发 |
| 服务器 | 每天定时发送（唯一开定时的一方） |

## 6. 什么时候需要重新登录

| 情况 | 处理 |
|---|---|
| 账号页提示「剩余 N 天」（N ≤ 3） | 尽快重新扫码 |
| 发送全失败，日志提示登录态失效 | 重新扫码 |
| 换电脑 / 重装系统 | **先把 `data/accounts/` 整目录备份出来**，新机器上放回去通常就不用重新扫 |
