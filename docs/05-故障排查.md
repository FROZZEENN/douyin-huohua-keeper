# 05 · 故障排查

按**症状**索引。每条都是「现象 → 原因 → 怎么处理」。

排查前建议先跑一次自检，它会直接指出环境问题：

```bash
python scripts/healthcheck.py
```

---

## 打不开工作台

| 现象 | 原因 | 处理 |
|---|---|---|
| **401** | 令牌没带或不对 | 重新输入 `.env` 里 `HUOHUA_TOKEN` 的值；也可以在地址后加 `?token=xxx` 打开一次（浏览器会记住） |
| **429** | 令牌连错 5 次 | **等 60 秒**。这是刻意的下限防护，防止无限次猜令牌 |
| **403** | 你的 IP 不在白名单 | 改 `.env` 的 `HUOHUA_ALLOWED_IPS`；出口 IP 常变的话直接清空它，改靠令牌保护 |
| 连不上 | 端口没放行 / 服务没起 | 服务器安全组放行 `8787`；`docker compose ps` 看容器是不是 healthy |

## 扫码与登录

| 现象 | 原因与处理 |
|---|---|
| 一直卡在「需在手机上进行确认」 | 说明你**在没有图形界面的机器**上做首次登录（服务器 / 容器里）。回到本机登录，再把 `data/accounts/main.state.json` 拷到服务器 |
| 二维码一直转、看不清 | 账号页有「登录页实时画面」，可以放大；专用扫码页是 `http://<地址>/scan.html?token=xxx` |
| 要填验证码但点不到输入框 | 用实时画面下方的输入框：先在「要填进」里选对是第几个框，再点「输入内容」 |
| 提示登录态快过期 | 账号页会显示剩余天数。过期后重新扫码；**换机器前先备份 `data/accounts/`** |
| 一登录就被顶掉 | 同一个账号不要在**两个实例**上同时跑定时发送（既容易触发风控，也会互相顶号）。本地只用来登录和调试，定时交给服务器 |

## 发送

| 现象 | 原因 | 处理 |
|---|---|---|
| **「找不到联系人」** | 名字和抖音里的显示名不完全一致；或者这个人本来就不在好友会话里 | 先点「同步好友列表」刷新；核对名字**一字不差**（含空格和表情） |
| **「结果不确定」** | 消息**很可能已发出**，只是会话列表的预览没变化 —— 抖音常把预览换成系统提示 | **手动打开那个会话看一眼**。工具不会自动重发，就是为了避免重复发送 |
| 提示找不到输入框 | 抖音页面结构变了 | 本机设 `HUOHUA_HEADLESS=false` 看一眼实际页面；同时看 `logs/huohua.log` |
| 演练正常、真发失败 | 演练只走到「准备好」，不点发送，所以验证不到发送那一步 | 看日志里失败那一环的具体报错 |

## 浏览器与环境

| 现象 | 处理 |
|---|---|
| `Executable doesn't exist` | `playwright install chromium chromium-headless-shell` —— **两个都要装** |
| 内存占用偏高 | 共享浏览器空闲 600 秒后自动回收；想更激进就调小 `HUOHUA_ENGINE_IDLE_TIMEOUT_SEC` |
| 自检报 Chromium 有问题 | `python scripts/healthcheck.py` 会给出具体的修复命令 |
| 想看它到底在干什么 | `HUOHUA_HEADLESS=false`（本机），会弹出真实浏览器窗口 |

---

## 定时任务

| 现象 | 检查 |
|---|---|
| 到点没发 | 看首页横幅的「下次运行」；或查 `/api/system/overview` 的 `next_run_at`、`job_count`（正常是 **2**） |
| 时间不对 | 时区固定 `Asia/Shanghai`；时间在**任务页**改，存在 `data/config/tasks.json`（优先于环境变量） |
| 一直卡着不动 | 可能残留 `data/.run.lock` —— 确认没有任务在跑后删掉它（工具自己也会清理过期锁） |
| 想让本机不自动发 | `HUOHUA_ENABLE_SCHEDULER=false`，或 `./scripts/dev.sh run`（默认就关掉定时） |

## 通知（Server酱 等）

| 现象 | 说明 |
|---|---|
| 今天全成功却没收到推送 | **这是设计**：成功不打扰，只有失败 / 异常才推 |
| 收不到每日汇总 | **今天一切正常就不会推**（2026-09 起的策略：只在出问题时提醒）；另外需要配置了通知通道 |
| 想验证通道通不通 | 系统设置页的「通知测试」 |
| 想改告警阈值 | `HUOHUA_WARN_THRESHOLD` / `HUOHUA_CRITICAL_THRESHOLD` |

---

## 数据与日志都在哪

| 路径 | 内容 |
|---|---|
| `data/config/contacts.json` | 收件人名单与各自的开关 |
| `data/config/tasks.json` | 时间、文案池、发送间隔 |
| `data/accounts/*.state.json` | **登录态（等同密码）** |
| `data/runs/<run_id>/` | 每次运行的报告 |
| `logs/huohua.log` | 运行日志（排查时第一个该看的地方） |

> ⚠️ `data/` 和 `.env` 都**不该进版本库**（已在 `.gitignore` 里）。
> 备份时记得它们包含登录态，请按密码级别的敏感度对待。
